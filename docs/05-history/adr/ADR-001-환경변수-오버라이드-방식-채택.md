# ADR-001: Spring profile 분리 대신 환경변수 오버라이드 단일 설정 채택

## 맥락 (Context)
최초 설계는 `application-local.yml`/`application-test.yml`처럼 Spring profile(`local`/`test`)을 분리하는 안을 검토했다. local(개발 PC)과 사내 테스트 서버 두 실행 환경을 지원해야 했다.

## 결정 (Decision)
Spring profile을 분리하지 않고, `application.yml` 하나에 `${DB_HOST:localhost}` 형태의 환경변수 기본값을 넣어 실행 시점에 오버라이드하는 방식을 채택했다. `docker-compose.yml`도 local/test용으로 파일을 나누지 않고 단일 파일을 유지하며, `backend` 서비스의 `environment` 블록에 실제 값을 직접 넣는다. 프론트엔드도 `.env.local`/`.env.test` 대신 Docker 빌드 시점 ARG(`VITE_API_BASE_URL`)로 처리한다.

## 근거
- profile 분리보다 구성 파일 수가 줄어 관리 부담이 적다
- 실행 환경이 로컬/사내 테스트 서버 2가지뿐이라 profile의 이점(N개 환경 분기)이 크지 않다

## 결과 (Consequences)
- 장점: 설정 파일이 하나뿐이라 드리프트(파일 간 불일치) 위험이 없음
- 단점: 환경변수를 빠뜨리면 기본값(localhost 등)으로 조용히 폴백될 수 있어, 배포 시 환경변수 체크리스트가 필요함
- 실제로 이 방식 때문에 nginx `/api` 프록시 누락 장애를 한 번 겪었다(02-architecture.md §2.4 참고) — `VITE_API_BASE_URL=/api` 상대경로 채택이 이 ADR과 맞물려 있음
