## 이 문서의 목적

Light ALM v3 확장(01-scope.md §1.2 v3 항목)은 업계에서 널리 쓰이는 상용 ALM 툴들에서 흔히 볼 수 있는 **일반적인 기능 카테고리**(다단계 검토, 시점 스냅샷 비교, 위험 등록, 문서형 요구사항 열람, 대시보드 커스터마이징 등)를 참고해서 설계됐다. 이 문서는 (1) 어떤 성격의 기능을 참고했고 어디까지만 참고했는지, (2) 저작권 관련 준수 원칙을 명시해서, 이후 어떤 세션이 이 문서를 보더라도 같은 원칙을 지키도록 한다. **특정 제품명은 이 문서를 포함해 프로젝트의 어떤 문서에도 적지 않는다** — 아래 원칙 참고.

## 저작권 준수 원칙 (일반 정보 — 법률 자문 아님, 상업 배포 전 법률 검토 권장)

1. **기능·개념만 참고한다.** "업계에 이런 개념의 기능이 흔하다"는 사실은 자유롭게 참고할 수 있다(저작권은 아이디어가 아니라 표현을 보호). 워크플로우 구조, 데이터 모델 개념 등은 참고 대상이다.
2. **UI, 문서 텍스트, 로고, 소스코드는 절대 복제하지 않는다.** 스크린샷을 참고자료로 첨부하지 않는다. 특정 제품의 도움말/문서 문장을 옮기지 않는다.
3. **기능명은 우리 프로젝트 고유 용어로만 서술한다.** 특정 제품의 상표화된 기능명을 쓰지 않는다 — 일반명사로만 서술한다.
4. **특정 제품명·회사명을 문서에 직접 적지 않는다.** 어떤 제품을 참고했는지 유추할 수 있는 고유 기능명(브랜드화된 용어)도 인용하지 않는다. 참고 배경을 설명할 때는 "업계에서 흔히 쓰이는 상용 ALM 툴", "일반적인 형상관리 개념"처럼 일반화된 표현만 사용한다.
5. **디자인(색상/레이아웃/아이콘)은 특정 제품을 참고하지 않고 이 프로젝트의 자체 디자인 시스템**(`02-design/design-tokens/linear-style-tokens.md`)**하나로 통일한다.**

## 참고한 기능 카테고리 → 우리 프로젝트 명칭 매핑

| 업계에서 흔한 기능 카테고리 (일반 설명) | 우리 프로젝트 명칭 | 우리 관점의 설명 (독자 작성) | 상세 설계 위치 |
|---|---|---|---|
| 다단계 검토/승인 프로세스 | **리뷰 사이클 (Review Cycle)** | 기존 §1.2의 좁은 승인 게이트(DRAFT→APPROVED 1건)를 확장해, 여러 검토자를 지정하고 각자 승인/반려/의견만 남기는 방식을 지원. 범용 워크플로우 엔진은 여전히 아님(01-scope.md §1.3 원칙 유지) | 03-data-model.md §3.18~3.19 |
| 특정 시점 상태 고정/비교 | **베이스라인 (Baseline)** — 소프트웨어 형상관리에서 일반적으로 쓰이는 용어 | 요구사항/이슈/테스트케이스의 특정 시점 상태를 스냅샷으로 고정해 이후 변경 사항과 비교 가능하게 함 | 03-data-model.md §3.20~3.21 |
| 요구사항/이슈가 여러 단계 계층을 이룰 때 상위-하위 관계와 연결된 항목을 한 화면에서 재귀적으로 탐색하는 기능 | **상위/하위 추적성 트리 뷰** | 요구사항 조상 체인 + 하위 요구사항·연결된 이슈까지 트리 구조로 표시(이미 구현됨, 05-frontend.md §5.4) | 05-frontend.md §5.4 |
| 위험 식별/평가/완화 관리 | **위험 관리 (Risk Register)** | 요구사항/이슈에 연결 가능한 위험 항목을 등록하고 발생가능성×영향도로 점수화. 정식 방법론 전체를 구현하지는 않음(간이 스코어링만) | 03-data-model.md §3.22 |
| 요구사항을 표/카드가 아닌 문서 형태로 편집·열람 | **요구사항 문서 뷰 (Requirement Document View)** | 기존 상위/하위 계층 구조(parent_requirement_id)를 문서 목차처럼 순서대로 나열해서 보여주는 읽기/편집 뷰. 별도 문서 편집기 엔진을 새로 만들지 않고 기존 계층 데이터를 다르게 렌더링하는 방식 | 05-frontend.md §5.11 |
| 여러 제품 라인에 요구사항 재사용 | **변형 관리 (Variant Management)** — 시스템 엔지니어링 일반 용어 | 요구사항에 "변형(제품 라인)" 태그를 붙여, 변형별로 포함/제외/수정 여부를 표시 | 03-data-model.md §3.23 |
| 커스텀 대시보드 위젯 | **대시보드 위젯 설정** | 사용자가 대시보드에 표시할 위젯 종류/배치를 선택 | 03-data-model.md §3.24 |
| Excel/PDF 리포트 내보내기 | **리포트 내보내기** | 추적성 매트릭스, 테스트 실행 결과, 감사 로그 등을 Excel/PDF로 내보내는 API | 04-api.md §4.21 |

## 참고하지 않은 것 (명시적 제외)

- 정식 FMEA/위험관리 방법론 전체 — 간이 점수화만 구현
- 리치 텍스트, 표, 이미지 삽입이 가능한 워드프로세서급 문서 편집기 — 기존 계층 데이터를 읽기 중심으로 재구성해서 보여주는 수준까지만
- 특정 제품의 UI 컴포넌트, 색상, 아이콘, 로고, 문서/도움말 텍스트
- 특정 제품명을 이 프로젝트의 기능명·화면명·문서에 사용하는 것

## Light ALM 철학과의 긴장 관계에 대한 메모

01-scope.md §1.1은 "무거운 ALM 툴 없이" 핵심 기능만 관리하는 것을 목적으로 명시하고 있다. 이번 v3 확장(4개 카테고리)은 이 철학과 다소 긴장 관계에 있다 — 기능이 늘어날수록 "Light"에서 멀어질 위험이 있다. 그래서 각 기능은 **업계 일반 개념의 일부만, 최소 스코프로** 들여왔다(위 "참고하지 않은 것" 목록 참고). 앞으로 추가 확장을 검토할 때도 이 원칙(요구사항 분석가가 "이게 정말 최소 스코프인가"를 매번 검증)을 유지할 것을 권장한다.
